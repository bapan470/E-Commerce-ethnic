FIX — STATE NOT UPDATING WHEN PIN CODE CHANGES
=================================================

Bug: City auto-filled correctly on a new PIN code, but State stayed
stuck on whatever it was before (e.g. always "Goa").

Cause: once City/State held a value from a saved draft (or an earlier
manual pick), the code treated that as "the shopper's own value" and
refused to let a new pincode overwrite it — City happened to keep
updating in your test because its draft value was empty, State did not
because it had a leftover value.

Fix: typing a new PIN code now always lets the lookup refresh both City
and State for that pincode, no matter what they held before. If you
edit City or State by hand afterwards, that still sticks (won't get
overwritten) — this only resets on typing a new PIN code.

File changed
-------------
  app/checkout/page.tsx

How to apply
-------------
Copy this file into your local clone, overwriting the existing
app/checkout/page.tsx, then:

    git add app/checkout/page.tsx
    git commit -m "Fix: State field wasn't updating when PIN code changed"
    git push
